A console that tells the truth, a first day that works, and work that stops getting lost.

OpenRemote is one window for the agent harnesses on your computer - Claude Code, Codex, grok, pi, opencode, agy - running side by side. The daemon and the console only talk to each other on 127.0.0.1. Local chats never leave the machine, there is no telemetry, and nothing here needs an account.

This release is mostly about trust. A list that has not heard back from the daemon no longer reads as an empty one, a chat whose harness is waiting on you now says what it is waiting for, and a computer with no agent installed offers to fix that instead of ending its first run saying everything is ready.

## A console that stops lying about its state

- **A list that has not answered is not a list that is empty.** Lists say they are reading until the daemon replies, and the sidebar no longer claims "No chats yet" before it has asked. A project with no chats still says it is a project.
- **A dead daemon is named, not spun on.** One thin row above the main area says the daemon stopped answering (or never answered), quotes its own words when it has them, and offers Restart when this build can start it. A daemon that is still booting is not reported as a dead one.
- **A view that fails takes its pane, not the window.** If a screen throws while drawing itself, that pane answers with one plain sentence about the kind of failure, the error's first line and frame, and Try again once. The sidebar, the titlebar and the other panes keep working.
- **Failures say whose words they are.** An error from a harness reads as the harness's; an error from the daemon reads as the daemon's.
- **The numbers have names.** Metrics rows say what they count instead of standing alone as numbers.

## A first day that works

- **A computer with no agent is offered one.** Setup notices when no agent is installed and offers the installer right there, instead of reaching the end with a composer that cannot send. Skipping goes to the end, which says how to add one later.
- **Empty states say what the thing is for.** New chat with nothing to run on says what a harness is and where to install one. Plugins with no catalog, Marketplaces with nothing added, and Mobile with no phones in your Cloud each say what you are looking at and what comes next, and none of them shows a button that does nothing.
- **The window opens where it can be seen.** It fits the screen you actually have (the taskbar is not ours), remembers the size you chose, keeps your last position only while a piece of the titlebar is still on a connected monitor, and otherwise opens centred. A monitor you unplugged no longer decides how large your window is.
- **Removing things asks once.** A plugin, a marketplace, an endpoint, an MCP server, a project and a chat all offer the same two-step confirm, and Esc cannot throw away a half-written form.
- **The pairing code starts hidden.** On the Mobile screen the code is blurred until you press it, because a screen share should not hand a phone to whoever is watching.

## Work that does not get lost

- **Save a setup and pick it again.** New chat keeps a row of saved setups above the composer: a named chip for each, at most one of them the default that New chat opens on. A preset remembers what was true when you saved it, so it keeps only the model, effort and approval word the harness still offers, and says what it could not bring.
- **A waiting chat says what it is waiting for.** The Needs you group shows the harness's own question under the chat's title, cut to one line. The line never answers anything: a decision is still answered in the chat, where the options and the tool it asked about are on screen together.
- **Unread marks, and one page for what you missed.** A chat that moved while you were not reading it lifts one quiet step, and clears when you open it while the window is being looked at. Ctrl+K has a page listing what moved while you were away, with what happened last and when, and one press marks everything read.
- **Stop everything, and stop one harness.** One Ctrl+K action ends every running chat, asking with the number and naming the chats first; another stops only one harness's chats. A chat on another computer is named and skipped rather than reported as a failure.
- **Archive has a way back.** Archiving a chat shows "Archived" with Undo for eight seconds, from the hover button and the right-click menu alike.
- **The changes review.** "Changes in this chat" gathers every file a harness reported changing, folded by path, with a diff per file. It is what the harness reported, and says so: not a git diff, and not everything a turn did.
- **Copy a chat as Markdown.** One Ctrl+K action writes the chat out with who spoke, the tools it ran and how each decision was answered, ready to paste into a note or an issue.
- **Rename, save, restore.** A chat can be renamed from wherever it is. A chat's setup can become a preset. A pane layout can be named and restored later.
- **A dragged chat moves.** Dragging a chat onto a pane moves it there instead of streaming it in two panes, and a pane whose chat was deleted elsewhere becomes a New chat instead of pointing at nothing.
- **Drafts survive.** Switching between Local and Cloud no longer clears the project or the machine you chose, and a job draft cannot outlive the visit it was made for.

## Actions that stop hiding in menus

- **Ctrl+K is where actions live now.** The command palette holds the changes review, stop everything and stop one harness, a race of one prompt across several harnesses, turning a chat into a recurring job, saving and restoring layouts, renaming a chat, saving a chat's setup as a preset, marking everything read, and the list of what moved while you were away. A row that would do nothing is not offered.
- **One prompt, every harness.** Race sends the same prompt to two to four harnesses at once, one per pane, and refuses before creating anything when there are not enough harnesses or free panes.
- **The palette keeps the keyboard while it is open**, and a shortcut no longer eats what you were typing in a field.
- **Right-click works in a text field again.**

## For developers

- `npm run tauri:dev` runs the shell under its own bundle identity, so a dev build starts while the installed app is running, and a save that restarts the dev server no longer takes the window with it.
- The release workflow's format gate now installs the tools it judges with: CI fails on the code's formatting rather than on a missing `rustfmt`. The workspace still fails `cargo fmt --all --check` on a clean checkout, so a green CI needs one formatting pass once the work in those files has landed.
- The window geometry is a small pure module with tests: fitting the work area, keeping a grabbable titlebar on a connected monitor, and centring when the saved position is gone.

## Installing this

The installers are unsigned by decision, so Windows shows SmartScreen the first time: **More info**, then **Run anyway**. On macOS, right-click the app and choose Open. Android refuses an update whose version code does not exceed the one installed; this build's code is higher than the last. Linux gets an AppImage, and the machine installer for a headless computer carries a checksum file the install script refuses to ignore.

Upgrading keeps your chats, your settings and any paired phone.

Nothing is sent anywhere by this app. If you find something wrong, the issue tracker is the fastest way to tell us.
