A quiet release: the hardening pass. Nothing new - everything made
stronger, faster to trust, and harder to break.

OpenRemote is one desktop window for the coding-agent harnesses on your
machine - Claude Code, Codex, Grok Build, Pi Agent, OpenCode and
Antigravity - run side by side. A Rust daemon wraps the harness CLIs and
serves the console over localhost; the desktop app ships the daemon
inside, so nothing leaves the machine. No telemetry.

This version is the product of a full audit of the console, the daemon,
the harness drivers, the Cloud mesh, and the build pipeline - every fix
below was found by that audit, implemented, and re-verified by an
independent review.

## Answers that arrive, questions that wait

A structured question from Claude Code - the pick-one prompts - was
answered as a denial no matter what you clicked: your choice never
reached the model. It does now, in the harness's own words, end to end.

## A chat that keeps its numbers

The running cost and thinking-token totals used to snap back to zero
every couple of seconds. They don't anymore. Tool results also pair
with the right call now - parallel edits no longer swap their outputs.

## The console under strain

- A malformed frame no longer derails an event stream; it's skipped
  and the stream keeps reading.
- Every request the console makes now has a timeout, so a stuck daemon
  shows the error banner instead of spinning forever.
- A chat deleted on another device no longer keeps an empty pane
  retrying its stream.
- Big turns - a multi-thousand-line file write, a long streaming reply -
  no longer freeze the transcript; long output is capped with a note.
- "Reopen: Last view" finally restores the chat you were in, not the
  New chat screen.

## The daemon under failure

- A harness that crashes at boot fails the chat in seconds, not a
  minute of silence.
- Stopping a chat drains its last events and closes open decisions
  instead of leaving them answerable against a dead process.
- Closing the app sweeps the harness processes it started instead of
  orphaning them.
- On Windows, harness CLIs no longer flash a console window per
  prompt.
- A corrupt local database is set aside and rebuilt from the session
  logs instead of failing every start.
- Webhook-triggered automations deduplicate deliveries and cool down,
  so a sender's retries no longer open three chats.

## Cloud that recovers

- Signing back in after the backend rotates its auth (or after this
  device was removed and re-added) actually restarts the encrypted
  mesh; before, only a full restart did.
- A machine removed from the account can re-enroll with a fresh install
  code; before, one refusal locked it out forever.
- A dropped network connection mid-sync no longer strands a chat's
  replication.
- Devices with unusable keys are refetched instead of pinned broken.

## The installers and updates

- The Android build's internal version finally advanced: 0.3.2
  installs cleanly over 0.3.0 and 0.3.1. (Updating from 0.3.1 was
  blocked by a version-code bug in that release; uninstall-first
  works, but this is the proper fix.)
- The release pipeline preflights before building: version agreement
  across every manifest, release notes present, Android version code
  strictly higher - mismatches fail in seconds, not after a
  half-hour build.
- Rebuilds of a re-pushed tag no longer mix assets from two versions.
- The Linux machine installer's daemon download is checksum-verified
  against a published SHA256SUMS, as before, now built with a pinned
  toolchain.

## Also in this release

- Deleting a synced chat from the sidebar, archived-chat management in
  Settings (shipped on main since 0.3.1), and a calmer New chat
  layout.
- CI now compiles and lints the desktop shell itself on every push -
  before this pass, its first compile of a change was on a release
  runner.

## Install

- **Android:** open the APK and let it install. Updating from 0.3.1
  may require uninstalling first (see above); 0.3.2 and later update
  normally.
- **Windows:** run the installer. The daemon starts with the app; the
  token handshake is automatic. If you had 0.3.1 running, the new
  daemon replaces it on next start.
- **Linux:** `chmod +x` the AppImage and run it, or install the `.deb`.
  Machines enrolled via the install command pick the new daemon on
  their next `openremote-daemon` update or a re-run of the install
  command.
